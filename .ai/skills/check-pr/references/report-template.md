# Report template

Use this shape for the summary comment (CI mode) and the chat report (local mode). In CI mode the very first line must be the marker so later runs update this comment instead of adding a new one.

````markdown
<!-- check-pr -->
## 🔍 PR check: <Ready ✅ | Needs changes ⚠️ | Blocked ⛔>

**Commit:** `<short sha>` · **Model:** <model> · **Gate:** Lint ✅ Test ✅

<One or two plain sentences: the overall picture and the most important thing to fix first.>

| Severity | Count |
|---|---|
| ⛔ blocker | <n> |
| ⚠️ major | <n> |
| 💡 minor | <n> |
| ✏️ nit | <n> |

### Findings

#### ⛔ <short title>: `path/to/file.go:42`
**What:** <what is wrong, in plain words>
**Why it matters:** <the bug or risk it causes>
**Fix:**
```go
// short example of the fix
```

<repeat per finding, most severe first; minor and nit may be one-line bullets>

### Test cases

| Function | Case | Status |
|---|---|---|
| `WorkOrder.Start` | from `assigned` → `in_progress` | ✅ tested |
| | from `completed` → `ErrInvalidTransition` | ❌ missing |

<For each ❌: one sentence on why it matters, plus an example test row.>

### Conventions
- Commits: ✅ all match `<type>(<feature>): <message>` / ❌ `<subject>` doesn't
- PR template: ✅ filled / ❌ <what's missing>
- OpenAPI: ✅ updated / ➖ no endpoint changes / ❌ endpoint changed without OpenAPI
- Migrations: ✅ Up + Down / ➖ none / ❌ <problem>

<sub>Generated by the `check-pr` skill. Comment `@claude-code-review` to re-run, or `@claude-code-review deep` for a deeper review with a stronger model.</sub>
````

## Writing rules

- Most severe first. Group repeated instances of the same problem into one finding that lists every location.
- Every blocker and major has **What / Why it matters / Fix** with a code example; minor and nit can be one line.
- Plain language, beginner-friendly; explain Go terms the first time (e.g. "`%w` keeps the original error inside the new one, so `errors.Is` can still find it").
- No invented findings. If there's nothing to report in a section, write "None".
- Never paste secrets; point to `file:line`.
- Inline comments (CI mode) use the same What / Why / Fix shape, short, on the exact line.
